- 本地网关 8081 负责决策与能力分发，8082 仅做聚合转发；采用 hybrid-auto 严格本地优先策略，低置信度自动回退规则。
- feibot 框架按领域分派任务，要求执行端回报结论、验证方法及引擎信息，跨会话依赖任务卡记录状态与文件位置。
- 当前系统已建立分派规则与交接规范，但端到端自动化尚未验证，缺乏跨工作区持续可靠运行的效率对比数据。

**深度内容详析**:
作者在构建多 Agent 系统时，发现单纯优化单次模型调用（路由层）无法解决跨工具协作中的状态丢失与责任模糊问题，因此将架构拆分为两层。第一层是智能路由网关，由 8081 端口负责决策与能力分发，8082 端口仅做模型聚合转发。路由逻辑采用 hybrid-auto 策略，默认严格本地执行（hybrid-auto），仅在获得出站许可且本地不可用时才允许云端候选（hybrid-auto-cloud），并引入轻量决策模型 JEV 进行低置信度回退，确保数据安全。第二层是任务编排，由 feibot 框架接管，它不直接执行任务，而是根据领域表将需求分派给专业 bot，并强制要求执行端回报结论、验证办法、所用引擎及停止原因。跨会话交接依赖‘任务卡’记录目标、状态、文件位置与审批进度，确保上下文不丢失。尽管代码与规则已就绪，但作者强调目前缺乏跨 bot 持续自动运行的实证数据，端到端自动化仍处于验证阶段。

### [DeepSeek Harness 多任务 Agent 架构与注意力边界](https://www.huxiu.com/article/4902022.html?f=rss) ⭐️ 8.0/10 [人工智能与大模型]

**核心要点速览**:
- DeepSeek Harness 发布 Super-agent 原型，通过 Router/Worker 分层架构实现多任务并行处理，合成实验显示 p95 完成时间从 29.5 分钟降至 15.7 分钟。
- 核心机制在于 Router 统一对外分派上下文并隔离 Worker 执行，配合事件直通机制减少重复路由决策，但需明确授权边界与状态记录。
- 原型目前仅支持单 GitHub 仓库及可选飞书接入，存在提示注入、凭据泄露及跨设备控制风险，且部分主动规则尚未落地实现。
- 实验仅验证调度协作效率，未包含真实团队场景下的打断成本与返工数据，企业部署需先解决状态持久化与权限隔离问题。

**深度内容详析**:
DeepSeek Harness 团队针对多任务环境下人类注意力瓶颈提出解决方案，其核心在于将单任务依赖模型能力的局限转化为多任务依赖架构设计的挑战。通过 Router/Worker 分层架构，Router 作为中央协调器负责接收来自群聊、GitHub 等外部事件，过滤噪声后统一分派上下文，而 Worker 则被隔离执行具体任务并汇报结果，避免长任务阻塞新消息。实验数据显示，在合成消息流中，采用 Super-agent 方案的 p95 任务完成时间（15.7 分钟）显著优于单会话加 Subagent 方案（29.5 分钟），且引入事件直通机制后，Router 决策量减少约 30%，缓存 Token 读取量从 2323 万降至更低水平。然而，该架构的落地面临严峻挑战：首先，主动性的边界需通过显式授权规则界定，防止 Agent 越权操作；其次，状态与授权不能仅存于会话记忆，需持久化记录以支持跨会话交接；最后，原型目前仅覆盖单仓库场景，且存在提示注入、凭据泄露及跨设备控制等安全风险，企业级部署需额外构建隔离环境与审计机制。

rss · 虎嗅 · 10月31日 19:15

### [Linux TCP 零日漏洞 CVE-2026-98432 紧急修复](https://atlasum.net/blog/cve-2026-98432-linux-ipv4-tcp-uaf) ⭐️ 9.0/10 [技术与软件工程]

**核心要点速览**:
- CVSS 9.8 严重漏洞已在上游内核于 10 月 15 日修复，但 Ubuntu 和 RHEL 尚未发布补丁。
- 漏洞源于 IPv4 TCP 握手协议中 `tcp_v4_syn_recv_sock()` 函数未正确复制选项数据导致的内存使用错误。
- 虽然修复了，但部分服务器因单核限制或 ISP 路由器过滤 IP 选项而具有较低的实际风险。
- Anthropic 公司曾利用此漏洞在 MPTCP 服务器上执行 root 权限命令，凸显其利用潜力。

**深度内容详析**:
CVE-2026-98432 是 Linux 内核中一个极其危险的远程使用错误后（Use-After-Free）漏洞，CVSS 评分高达 9.8。该漏洞位于 IPv4 TCP 握手路径中，具体在 `tcp_v4_syn_recv_sock()` 函数里。当服务器监听带有 IPv4 选项的 TCP 数据包时，内核在处理 `ireq->ireq_opt` 所有权转移时，错误地将未复制的指针传递给子套接字，导致攻击者可以触发内存释放后的非法访问。上游社区在 2026 年 10 月 11 日和 15 日发布了包含四行代码修复的内核版本（如 5.10.272, 6.6.159 等）。尽管修复已就绪，但 Ubuntu 和 RHEL 等主流发行版尚未发布官方补丁，导致大量生产环境仍处于暴露状态。值得注意的是，Anthropic 公司曾利用此漏洞在支持多路径 TCP (MPTCP) 的服务器上成功执行 root 权限命令，这表明该漏洞在实际攻击场景中具有极高的可行性。

**背景**: Linux 内核是许多服务器操作系统的核心组件，负责网络协议栈的处理。使用错误后（Use-After-Free）漏洞通常发生在内存管理不当的情况下，攻击者可以通过精心构造的数据包触发内存破坏。CVSS 9.8 表示该漏洞具有极高的严重性，通常意味着远程未认证攻击者可以导致拒绝服务或完全的系统控制。
