### [Agent 权限失控怎么办？PM 必须划定的 3 条安全边界](https://www.woshipm.com/ai/6435148.html) ⭐️ 8.0/10 [产品经理]

一篇面向产品经理的新指南提出了三条核心安全边界——工具权限最小化、数据隔离和提示注入防护——以防止 AI Agent 权限滥用和数据泄露。 随着 AI Agent 的广泛部署，权限滥用和数据泄露风险日益增长；该指南帮助产品经理在设计阶段嵌入安全考虑，有可能在漏洞进入生产前就加以防范。 该指南强调安全必须在产品需求中定义，而非留给工程师处理，并提供了实用检查清单，涵盖工具白名单、会话级数据隔离和输入信任层级定义。

rss · 人人都是产品经理日榜 · 7月29日 06:27

**背景**: AI Agent 利用大语言模型（LLM）根据用户输入动态决定调用哪些工具，行为不可预测，攻击面更大。与传统软件的固定权限不同，Agent 可能通过提示注入（Prompt Injection）被操纵，精心构造的输入可绕过安全防护。数据隔离也至关重要，因为 Agent 可能无意中跨会话暴露用户数据，或通过 RAG 检索时因缺乏访问控制而泄露信息。

### [Graph Engineering：AI Agent 产品稳定上线的关键](https://www.woshipm.com/ai/6436079.html) ⭐️ 8.0/10 [产品经理]

一种名为 Graph Engineering 的新 AI 工程概念被提出，它专注于将多个不可靠的 AI 节点编排成一个稳定的产品系统。它将评估从模型输出转向系统行为，解决了 AI Agent 从演示到生产上线的核心挑战。 随着 AI Agent 越来越多地执行复杂的多步骤任务，传统的单轮评估已不再足够。Graph Engineering 提供了一个确保 Agent 工作流可靠性、一致性和成本效益的框架，这对于构建可信赖的 AI 产品至关重要。 Graph Engineering 不是知识图谱，而是任务执行图，节点和边代表 AI 步骤。关键评估指标包括任务成功率、节点通过率、工具调用准确率、路由准确率、状态一致性、人工介入率以及成本/延迟。

rss · 人人都是产品经理日榜 · 7月29日 04:19

**背景**: AI Agent 是能够使用工具和推理执行多步骤任务的系统，不同于仅回答单一查询的简单聊天机器人。传统的模型评估侧重于输出正确性，但 Agent 系统需要评估整个工作流。Graph Engineering 建立在 Prompt Engineering、Context Engineering、Agent Engineering 和 Loop Engineering 等早期概念之上，现在被讨论为管理 Agent 编排复杂性的一种方式。
