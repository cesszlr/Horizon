### [Linux 输入延迟：X11 与 Wayland 对比，含 VRR 和 DXVK](https://marco-nett.de/blog/measuring-input-latency-on-linux-x11-vs-wayland-vrr-dxvk/) ⭐️ 8.0/10 [技术]

一篇详细的技术文章测量并比较了 Linux 上 X11 与 Wayland 之间的输入延迟，包括可变刷新率（VRR）和 DXVK 转换层的影响。分析揭示了这些配置之间可测量的延迟差异。 这项分析为 Linux 用户（尤其是游戏玩家）提供了关键的客观数据，以理解 X11 与 Wayland 之间真实的延迟权衡。它有助于验证或挑战关于系统响应速度的主观感受，并可能指导显示服务器和图形驱动程序的未来发展。 测量使用了 500Hz 显示器，这可能掩盖了在常见 60Hz 或 120Hz 刷新率下更明显的延迟问题。XWayland 配置相比原生 Wayland 显示出约 3ms 的更高延迟，可能意味着整整一帧的延迟。

hackernews · hoechst · 7月14日 16:36 · [社区讨论](https://news.ycombinator.com/item?id=48909424)

**背景**: X11 和 Wayland 是 Linux 的显示服务器协议。X11 是传统系统，应用程序将绘图命令发送到中央服务器，而 Wayland 允许应用程序使用现代图形 API 直接渲染到缓冲区，从而可能降低延迟。可变刷新率（VRR）使显示器的刷新率与 GPU 的帧输出同步，以减少撕裂和卡顿。DXVK 是一个转换层，将 Direct3D 9/10/11 调用转换为 Vulkan，使 Windows 游戏能够通过 Wine 在 Linux 上运行。
